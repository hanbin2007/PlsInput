# PlsInput 设计文档（第一版）

日期：2026-09-14
状态：待用户评审

## 1. 一句话

每天一道题：用今天给的残缺键盘，在会腐烂的格子里拼出尽可能大的数，全服同题，Game Center 排名。

## 2. 目标与边界

**目标**
- 每天一局，2 到 4 分钟，规则一句话能讲清，但每天的最优打法不同。
- 四个元素互相咬合：腐烂（压力）、耐久（预算）、阈值道具（成长）、格子类型（策略）。
- 零后端：排行榜靠 Game Center，每日题靠日期种子，运营靠一份托管的只读 JSON。

**命名（假设，可改）**
- 英文名 PlsInput，中文显示名"请输入"，Bundle ID `cn.origenclub.plsinput`。

**第一版做**
- iPhone 竖屏，iOS 17 起，SwiftUI 原生。
- 简体中文、英文。
- 每日一局计分、练习模式不计分、每日榜、总榜、分享卡片、连胜。
- 远程配置 JSON：坏题替换、平衡参数、公告、最低版本。

**第一版不做**
- iPad、Mac 布局。
- 防作弊重放校验（状态机保持确定性，为将来留门）。
- 三选一起手、键词条、今日规则、主动交易（见附录 A）。
- 独立的多回合肉鸽模式（附录 A 的 C 模式）。
- 内购、广告、账号系统。

**已知取舍**
- 只做格子类型这一个策略系统，每天的节奏会相似。若上线后同质感明显，首选补"今日规则"（附录 A 的 D），实现成本最低。
- 分数记峰值而非结束值，更宽容，代价是拿到峰值后的收尾没有张力。

## 3. 一局的规则

### 3.1 界面

自上而下：大数显示区、表达式格子一排、背包（最多 3 格）、键盘。键盘每个键显示剩余耐久。顶部有"结束"按钮和腐烂计时的视觉提示。

### 3.2 格子

格子是有序列表。每个格子有类型和内容。内容为空、数字、或运算符。

| 类型 | 规则 |
|---|---|
| 普通格 | 数字按标准速度腐烂。 |
| 稳定格 | 内容不腐烂。 |
| 回声格 | 不能直接填。有效内容等于左边第二个格子的有效内容（含腐烂状态、含增幅后的值）。源为空或越界时回声为空。回声可以链式引用另一个回声。 |
| 增幅格 | 数字的有效值是当前腐烂后数字的两倍。9 显示为 18。 |
| 烂格 | 数字以两倍速腐烂，但往里填任何键不消耗耐久。 |

类型只影响数字，运算符在任何格子里行为一致。

### 3.3 输入操作

- 点键：填入第一个空格。目标格是回声格时跳过它找下一个空格。
- 点已填格子：选中。再点键：覆盖，这是"救"的动作。回声格不能被选中。
- 长按格子：清空，不耗耐久。
- 每次填入或覆盖消耗该键 1 点耐久，目标是烂格时不消耗。耐久为 0 的键置灰不可用，目标是烂格也不能用。
- 点背包道具再点目标：使用道具。

### 3.4 表达式语法

- 词法：相邻数字有效值按字符串拼接成一个整数字面量，例如 `1` `8`（增幅后）`9` 拼成 `189`。
- 运算符：`+`、`×`、`^`、`!`、`(`、`)`。
- 优先级由高到低：`!`（后缀，作用于前一个原子或括号组）、`^`（右结合）、`×`、`+`。
- 不合法的表达式：显示区显示一条横线，不参与峰值和阈值判定。空格子视为不存在，即 `9 ^ 空 9` 按 `9^9` 求值。
- 没有减法和除法，所以没有负数和除零。`0^0` 定义为 1，`0!` 定义为 1。

### 3.5 腐烂

- 每个数字从填入或覆盖那一刻起有独立计时。每过 R 秒数字减 1，减到 0 停住。
- R 由种子决定，范围见第 7 节；烂格用 R/2；稳定格不计时；回声格跟随源。
- 腐烂走"腐烂时钟"，不走墙钟。冻结道具生效期间、道具选择弹层打开期间、应用退到后台期间，腐烂时钟暂停。
- 一局从第一次按键开始计时。

### 3.6 阈值与道具

数值首次跨过下列阈值时发放该档道具，一档只发一次。一次求值可能连跨多档，按档位顺序逐个发放，需要选择的道具逐个弹层：

```
T1 = 10^3     T2 = 10^6      T3 = 10^12     T4 = 10^30     T5 = 10^100
T6 = 10^10^3  T7 = 10^10^10  T8 = 10↑↑4     T9 = 10↑↑5     T10 = 10↑↑7
```

阶梯上半段按"层数"拉开（10↑↑n 每加 1 约等于多一层幂塔），是 2026-09-14 用校准机器人跑出来的：原来的 T7 到 T10 挤在 10^10^6 到 10↑↑4 之间，一个 `!` 就能一口气跨完。

道具种类：

| 道具 | 效果 | 发放方式 |
|---|---|---|
| 解锁键 | 键盘加入一个新键，附带耐久 | 立即生效 |
| 加格 | 从本档给出的 2 到 3 种格子类型里选一种，再在表达式任意缝隙插入 | 弹层选择，选择期间腐烂暂停 |
| 改格 | 把一个已有格子改成本档指定的类型，内容保留；改成回声格时原内容丢弃 | 弹层选择目标格 |
| 修键 | 给一个键加 8 点耐久，只能修回该键的初始耐久上限，可复活已报废的键；背包已满且没有可修的键时作废 | 进背包 |
| 冻结 | 腐烂时钟暂停 10 秒 | 进背包 |

背包上限 3 个。背包已满时新获得的背包类道具必须立即使用。

生成约束：T1 必须解锁 `^`；起手键盘已经带 `^` 的日子，T1 改送 `!`。`!` 每多一个就多一层，是跳档键，只在 T4 及之后作为解锁键出现，耐久走单独的低区间（默认 3 到 5）。

校准机器人发现的两个坑，规则据此定下：解锁若落在 T2，1e6 靠 4 到 5 个纯数字格拼不到，整局卡死；`!` 太早出现，后面所有档在两三秒内被一口气跨完。

### 3.7 结束与分数

结束条件三选一，先到先算：
- 所有键耐久为 0 且背包里没有修键。
- 玩家点"结束"并二次确认。
- 腐烂时钟累计 300 秒。

分数是整局所有合法求值中的最大值（峰值）。每次状态变化和每次腐烂使数字变化时都求值一次。

结束后进入结果页：显示峰值、今日排名、分享按钮。每日模式在结束时向 Game Center 提交一次分数；练习模式不提交。

## 4. 每日题与练习

### 4.1 题号与种子

- 题日按 `Asia/Shanghai` 时区的日期计算。
- 种子字符串 `"PlsInput-v1-<yyyy-MM-dd><salt>"`，`salt` 默认为空，可由远程配置的 `dayOverrides` 指定。种子经 SipHash 或 FNV-1a 得到 64 位整数，输入 SplitMix64。
- 同种子必产生同题，生成器不得依赖任何外部状态。
- 首次进入当天的每日模式时，把生成好的题固化到本地存档。之后配置变化不影响已经开始的这一天。

### 4.2 每日题的内容

`DailyPuzzle` 包含：
- 起手格子：4 到 5 个，其中至多 1 个特殊格（稳定、增幅、烂格三选一；起手不出回声格）。
- 起手键：3 到 4 个数字键，从 1 到 9 抽，0 以低权重可能出现；1 到 2 个运算符键，从 `+`、`×` 抽，15% 概率其中一个换成 `^`。
- 每个键的初始耐久，各在区间内独立抽；总耐久不在校准区间内则整组重抽。
- 腐烂间隔 R。
- 十档奖励表。加格档附带 2 到 3 个候选类型；改格档附带目标类型。

### 4.3 生成约束

- 至少 2 个不同的数字键。
- 起手至少有 `+` 或 `×` 之一。
- T1 是 `^` 的解锁（起手已有 `^` 则是 `!`）；`!` 只在 T4 及之后出现。
- `(` 和 `)` 只作为解锁键成对出现，一档送两个键。
- 回声格是加格候选里最稀有的类型。
- 总耐久、R、起手格数落在远程配置 `balance` 给定的区间内。

### 4.4 练习模式

随机种子，走同一个生成器和同一套平衡参数，不限次数，不提交分数，本地记练习最高分。

## 5. 数值引擎

### 5.1 表示

自写 `BigNum`，移植 break_eternity.js 的子集：

```
sign: -1 | 0 | 1     本游戏只用 0 和 1
layer: Int           层数
mag: Double          尾数
含义：layer = 0 时值为 mag；layer ≥ 1 时值为 10^10^...^mag，共 layer 个 10
```

规范化规则与 break_eternity 一致：layer 0 时 mag 超过 9e15 升层；layer ≥ 1 时 mag 低于约 15.954 降层。

### 5.2 运算

只实现游戏需要的：整数构造、加、乘、乘方、阶乘、比较、超对数 `slog10`（线性近似）、十的迭代幂 `tetrate10`（解码用）。阶乘用 Stirling 近似：`log10(n!) ≈ n·log10(n) − n·log10(e) + 0.5·log10(2πn)`；n 处于 layer ≥ 1 时按 `n! ≈ 10^(n·log10 n)` 升层处理。

### 5.3 显示

显示算法，输入 (L, m)：

1. L = 0 且 m < 10^6：整数带千分位，如 `362,880`。
2. L = 0 且 m ≥ 10^6：`a.b×10^N`，如 `1.2×10^12`。
3. L ≥ 1：把 m 反复取 log10 直到 m < 10^9，每取一次 L 加 1；若此时 L ≥ 2，继续取到 m < 10^6。然后：
   - L = 1：`a.b×10^N`，N = floor(m) 带千分位，a.b = 10^(m − N)。`9^9^9` 显示为 `4.3×10^369,693,099`，读作"一个 3.7 亿位的数"。
   - 2 ≤ L ≤ 4：`10^` 重复 L 次再接 m，最多 2 位小数，去掉末尾的 0。`9^9^9^9` 显示为 `10^10^10^8.57`，`10↑↑4` 显示为 `10^10^10^10`。
   - L ≥ 5：`10↑↑h`，h 为 slog10 保留 1 位小数。

显示由 `Formatter` 统一负责，排行榜、结果页、阈值提示复用。

### 5.4 分数编码

Game Center 分数是 64 位整数，需要单调映射：

- `score = floor(slog10(v) × 10^12)`。`slog10` 单调，10^12 的分辨率足以区分实际会出现的相邻值，用随机属性测试保证。
- `context` 字段打包 `layer`（低 16 位）和 `Float32(mag)` 的位模式（次 32 位），用于在自绘排行榜里还原显示。

## 6. 远程配置

### 6.1 托管与获取

- 地址默认为 `https://kn.origenclub.cn/plsinput/config.json`，这是用户现有的阿里云服务器，静态文件由现有 kn-deploy 流程发布。这是假设，地址可在构建配置里改。
- 应用启动时和进入每日模式时拉取，距上次成功拉取不足 1 小时则跳过。超时 5 秒。
- 失败时用本地缓存，缓存也没有时用内置默认配置。内置默认配置与仓库 `remote/config.json` 的初版一致。
- 只读，无鉴权。

### 6.2 结构（schemaVersion 1）

```json
{
  "schemaVersion": 1,
  "configVersion": 1,
  "minAppBuild": 1,
  "notice": { "zh-Hans": "", "en": "" },
  "balance": [
    {
      "applyFrom": "2026-09-15",
      "startSlots": [4, 5],
      "digitKeys": [3, 4],
      "opKeys": [1, 2],
      "keyDurability": [6, 15],
      "factorialUses": [3, 5],
      "totalDurability": [45, 80],
      "rotInterval": [2.5, 4.0],
      "thresholds": ["1e3", "1e6", "1e12", "1e30", "1e100", "10^10^3", "10^10^10", "10^^4", "10^^5", "10^^7"],
      "rewardWeights": { "unlockKey": 30, "addSlot": 30, "convertSlot": 15, "repair": 15, "freeze": 10 },
      "slotKindWeights": { "normal": 20, "stable": 25, "amp": 25, "rotten": 20, "echo": 10 },
      "repairAmount": 8,
      "freezeSeconds": 10,
      "runCapSeconds": 300
    }
  ],
  "dayOverrides": {
    "2026-09-30": { "seedSalt": "-alt1" }
  }
}
```

`thresholds` 由 `BigNum` 的字符串解析器解析，支持 `1e3`、`10^10^3`、`10^^4` 三种写法。

### 6.3 应用规则

- `balance` 是数组，取 `applyFrom` 不晚于题日的最新一条。发布时约定 `applyFrom` 至少是明天，避免当天玩家拿到不同的题。
- `dayOverrides` 只支持 `seedSalt`，用于替换一道坏题；整天的题仍由生成器产生，保持确定性。
- `minAppBuild` 大于当前构建号时，首页显示更新提示并禁用每日模式，练习模式仍可用。
- `notice` 非空时在首页显示一条公告。
- 已固化的当天题不受后续配置影响。

## 7. 排行榜

- App Store Connect 配置两个榜：`daily` 为周期性榜，起始 2026-09-15 00:00 Asia/Shanghai，每 1 天重置，排序取最高分；`alltime` 为经典榜，取最高分。
- 每日模式结束时提交一次到两个榜，携带 `context`。
- 排行榜页自绘：每日与总榜两个标签，各显示前 100 名与本人位置，可切换只看好友。分数显示用第 5.3 节的格式，从 `context` 还原。
- 未登录 Game Center 可以玩，结果页提示登录后进榜。
- 题日边界与榜的重置时间一致，都是北京时间零点。

## 8. 客户端架构

### 8.1 仓库结构

```
PlsInput/
  Package.swift                 Swift Package：PlsInputCore 库、plsbot 可执行、测试
  Sources/PlsInputCore/
    BigNum/                     表示、运算、slog、格式化、分数编码
    Expression/                 词法、解析、求值
    Puzzle/                     模型、平衡参数、生成器、种子
    Run/                        一局状态机：状态、动作、事件、tick
    Config/                     远程配置模型与应用规则（纯逻辑）
  Sources/plsbot/               校准机器人
  Tests/PlsInputCoreTests/
  App/
    project.yml                 XcodeGen
    Sources/                    SwiftUI 视图、GameKit 适配、网络、存档、分享
    Resources/                  String Catalog、内置默认配置
  remote/config.json            托管的远程配置源文件
  docs/superpowers/specs/
```

### 8.2 核心状态机

`RunEngine` 是纯值类型逻辑，不依赖 UI 和时间 API：

- 输入：`apply(action, at rotClock)` 和 `tick(to rotClock)`。动作包括按键、选格、覆盖、清空、使用道具、加格选择、改格选择、结束。
- 输出：新状态和事件列表。事件包括数值更新、峰值刷新、跨阈值、道具获得、键报废、需要选择、结束。
- 腐烂时钟由外层推进，外层负责在冻结、弹层、后台时不推进它。
- 确定性：同一题、同一动作序列、同一时钟序列，结果完全一致。这是将来做重放校验的基础，也是测试的基础。

### 8.3 App 层

- `GameViewModel` 用 100 毫秒定时器推进腐烂时钟并调用 `tick`，把事件翻译成动画和震动。
- `GameCenterService` 负责登录状态、提交、拉榜。
- `ConfigService` 负责拉取、缓存、选取生效的平衡参数。
- `Store` 用 JSON 文件存于 Application Support：当天题与结果、历史结果与连胜、练习最高分、配置缓存。
- 页面：首页（今日状态、开始、练习、排行榜、连胜、公告）、对局页、结果页、排行榜页、设置页（Game Center 状态、震动开关）。
- 分享：生成一张文字卡片，内容为题号、峰值、排名，走系统分享面板。

### 8.5 动效与新手引导

动效遵循两条原则：按下即反馈、界面动效不超过 300 毫秒；弹簧默认临界阻尼，只有跨阈值和结果页这类庆祝时刻允许弹跳。系统开启"减弱动态效果"时，抖动、粒子、漂浮背景全部关闭，只保留淡入淡出。

| 时刻 | 反馈 |
|---|---|
| 按键 | 键帽缩到 0.94 并提亮，耐久数字用数值过渡往下滚 |
| 数值变化 | 显示区数字用数值过渡，数越大金色光晕越强 |
| 峰值刷新 | 显示区轻微放大一下 |
| 数字腐烂掉一格 | 该格子抖一下，数字颜色按值变暖变红 |
| 跨阈值 | 全屏一闪、显示区粒子爆发、阶梯上该档图标弹跳发光、震动 |
| 键报废 | 键帽抖动、变灰、震动 |
| 加格 | 新格子从 0.9 缩放淡入，其余格子平移让位 |
| 冻结 | 屏幕边缘冰霜色渐变、显示区蓝边、雪花图标脉动 |
| 结果页 | 峰值弹入加粒子，各行交错淡入 |
| 首页 | 漂浮的数字与运算符背景，卡片交错入场 |

新手引导是一局固定的教程题（慢腐烂，四档奖励依次是解锁 `^`、加格、冻结、修键），十四步引导气泡，自动步骤在状态满足条件时前进，手动步骤点"继续"。引导期间无关区域压暗到 30%。首次启动自动进入，可随时跳过；首页"怎么玩"可重玩，"规则"和对局页右上角的问号打开规则速查。

### 8.4 错误处理

- 配置拉取失败静默降级，不打断玩法。
- Game Center 提交失败时把待提交分数存本地，下次启动重试，一天只提交最高的那次。
- 对局中应用退到后台：腐烂时钟暂停。对局状态在每次动作后落盘，应用被杀掉后重开时从落盘处继续，中断期间不计入腐烂时钟。这样"杀掉重来"拿不到第二次机会。
- 数值引擎遇到超出表示范围的情况（理论上不会）按上限值处理并记录日志。

## 9. 测试与校准

- 测试框架用 Swift Testing，`swift test` 在 Mac 上直接跑，不依赖模拟器。
- `BigNum`：对照已知值（`9^9^9` 的 layer 与 mag、`(9!)!` 的量级、`10↑↑4`），比较的全序性，编码单调性的随机属性测试。
- `Expression`：优先级、右结合、后缀阶乘、括号、拼接、空格跳过、不合法输入。
- `Puzzle`：同种子同题、所有生成约束在一万个种子上成立。
- `Run`：脚本化动作序列验证腐烂时序、耐久扣减、烂格免耗、回声链、增幅拼接、连跨多档、阈值只发一次、背包满立即使用、三种结束条件、状态编解码后继续得到相同结果。
- `Config`：`applyFrom` 选取、`dayOverrides` 生效、`minAppBuild` 判定、缓存降级。
- `plsbot`：贪心机器人跑未来 365 天的种子加若干随机种子，输出峰值分布、到达各阈值的时间、报废前的按键数。用它调第 6.2 节的区间，并在上线前排查坏题。

## 附录 C：校准记录（2026-09-14）

用 `plsbot` 跑 565 个种子（未来 365 天加 200 个随机），决策间隔 1.0 秒模拟真人。

**第一轮（原规则）**：35% 的日子在 T1 卡死，因为解锁落在 T2 而 1e6 靠纯数字拼不到；`!` 一到手后面九档在两三秒内全跨完；平均一局 48 秒；耐久从不耗尽。

**改动**：T1 固定解锁 `^`；起手键盘永远没有 `^`（原 15% 概率会造成"起手带 ^ 再送 !"的暴击日）；`!` 只在 T4 及之后出现，耐久 3 到 5；阈值上半段改为 10^10^10、10↑↑4、10↑↑5、10↑↑7；修键封顶到初始耐久（否则机器人会给 `!` 修 8 点，等于白送 8 层）。

**第二轮（现规则）**：

| 指标 | 数值 |
|---|---|
| 峰值 slog10 分位 | p10 2.5，p50 4.1，p90 7.5，最高 10.8 |
| 各档到达率 | T1–T4 约 100%，T5 91%，T6 89%，T7 82%，T8 57%，T9 35%，T10 14% |
| 平均一局 | 92 秒，39 次按键，跨 7.7 档 |
| 结束原因 | 主动结束 92%，时间上限 8%，耐久耗尽 0% |

耐久探针：每键耐久降到 4 到 9，各档到达率不变。结论是格子数和键的种类决定上限，耐久只在真人手慢、反复救格子时起作用，默认值暂不动。
